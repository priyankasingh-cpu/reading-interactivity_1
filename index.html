📄 Inspect & Configure templates/deployment.yaml

Scenario: Your image-classification model takes 120 seconds on a cold start to load weights into GPU VRAM. Once loaded, it serves traffic on /ready and reports process health on /healthz. Click any probe block below to inspect its role, then tune the parameters on the right so the pod survives startup without entering CrashLoopBackOff.
spec:
  containers:
  - name: inference-service
    image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
Hotspot 1: Cold-Start Guard
    startupProbe:
      httpGet: { path: /healthz, port: 8080 }
      periodSeconds: 10
      failureThreshold: 6 # Budget = 60s
Hotspot 2: Traffic Gate
    readinessProbe:
      httpGet: { path: /ready, port: 8080 }
      periodSeconds: 5
Hotspot 3: Hang Recovery
    livenessProbe:
      httpGet: { path: /healthz, port: 8080 }
      initialDelaySeconds: 0
      periodSeconds: 15
      timeoutSeconds: 1
startupProbe: Temporarily disables liveness and readiness checks while the container loads multi-gigabyte model weights. Total startup budget = failureThreshold × periodSeconds.
